# 협업 흐름

PM은 GitHub Projects에서 한 번에 확인할 수 있는 크기의 이슈를 만들고 담당자, 목적, 변경 범위와 완료 기준을 적는다. 담당자는 `main`에서 이슈 브랜치를 만들어 작업하고 PR로 변경을 공유한다.

PR에는 연결된 이슈, 바뀐 동작, 화면과 서버의 요청·응답 형식에 미치는 영향, 실행한 로컬 확인 방법과 결과를 적는다. 환경 설정이나 문서가 바뀌면 함께 알린다. 담당자의 자체 확인 뒤 PM과 관련 담당자가 검토하고, 지적된 문제는 담당자가 수정해 다시 확인한다. 확인을 마친 변경은 개인별 의미 있는 커밋과 브랜치·PR 이력을 검토할 수 있도록 병합 커밋 방식으로 병합하는 것을 권장한다.

팀원마다 의미 있는 커밋을 최소 10개 남긴다. PM의 실제 문서 기여도 의미 있는 개인 커밋으로 센다. 수를 맞추기 위한 빈 커밋이나 실제 이력과 다른 기여 기록은 만들지 않는다. 팀 역할과 개인별 작업 요약은 문서와 PR·커밋 이력에서 일치하게 유지한다.
