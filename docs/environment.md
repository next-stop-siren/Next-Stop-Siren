# 공통 개발 환경과 인계

## 공통 환경의 소유와 구성

PM이 React·TypeScript 프론트엔드, FastAPI 백엔드, PostgreSQL의 최초 공통 환경을 한 저장소에 구성하고 설정 변경을 검토한다. 개발자는 PM이 제공한 프로젝트 파일과 안내를 받아 설치하며, 각자 프로젝트를 새로 초기화하지 않는다. 공통 설정은 하나의 설정 브랜치에서 화면과 서버의 연결까지 확인하고 검토를 거쳐 `main`에 병합한다. 그 뒤 개발자가 최신 `main`에서 각자 이슈 브랜치를 만든다. 프론트엔드와 백엔드의 영구 분리 브랜치는 두지 않으며 `main`에서 직접 개발하지 않는다.

최초 통합 인계물에는 기본 화면, FastAPI 상태 확인 엔드포인트, 로컬 PostgreSQL 연결, 프론트엔드에서 API로 보내는 최소 연결 확인 요청이 포함된다. 이 단계의 연결 확인은 인증이나 채팅 기능을 대신하지 않는다. 로그인·JWT·챗봇 구현은 이후 담당자의 제품 이슈에서 진행한다.

## PM이 제공할 실행 자료

PM은 팀이 같은 환경을 재현하도록 다음 자료를 저장소와 인계 안내에 제공한다.

- 프론트엔드·백엔드·데이터베이스에 필요한 도구의 고정 버전과 각 도구의 버전 확인 방법
- 의존성 잠금 파일과 해당 잠금 파일을 기준으로 설치하는 방법
- 프론트엔드, API, 데이터베이스의 공통 시작·중지 명령과 연결 확인 명령
- 로컬 개발 확인·빌드의 공통 명령, 로컬 운영용 빌드 실행·검증 방법과 각 단계의 성공 기준
- 비밀값이 없는 환경 변수 예시 파일: 변수 이름과 용도를 적고 실제 비밀값은 포함하지 않는다.
- macOS와 Windows에서 각각 시험한 설치·실행 순서 및 운영체제별 차이

정확한 버전과 명령은 실제 구성 및 두 운영체제의 검증 결과가 확정된 파일에 기록한다. 이 문서는 아직 제공되지 않은 버전이나 실행 명령을 정하지 않는다.

## 팀 설치·갱신과 문제 복구

팀원은 제공된 버전을 확인하고 잠금 파일로 의존성을 설치한 뒤, 예시 환경 변수를 기준으로 자신의 로컬 값을 설정한다. 공통 명령으로 데이터베이스와 서버, 화면을 시작하고 상태 확인 엔드포인트, 데이터베이스 연결, 화면에서 API로의 연결 확인 결과를 점검한다. 이어 로컬 개발 확인과 빌드를 수행하고, 운영용 빌드를 로컬에서 실행해 기본 화면과 API 연결을 다시 확인한다. 확인 결과와 실행 환경을 이슈나 PR에 남긴다.

설치나 실행이 꼬이면 제공된 안내에 따라 의존성·빌드 캐시를 정리하고 잠금 파일 기준으로 다시 설치한다. 캐시 복구 과정에서 로컬 데이터베이스를 삭제하지 않는다. 잠금 파일이나 공통 설정을 바꿔야 할 때는 담당자가 변경 이유, 영향받는 환경, 재현·검증 결과를 PR에 기록하고 PM이 검토한다. 승인된 변경은 잠금 파일과 macOS·Windows 안내, 관련 공통 명령을 함께 갱신한 뒤 팀에 알린다.

## 배포 전 확인과 출시 준비

개발 환경에서의 통합 확인과 로컬 운영용 빌드 검증을 마친 뒤 GitHub Actions를 통한 AWS 배포를 진행한다. CI는 이미지를 한 번 빌드하고 같은 이미지를 다음 환경으로 승격하며, 배포 대상의 아키텍처와 이미지 아키텍처가 맞는지 확인한다. AWS 설정, HTTPS, 비밀값 관리는 별도 출시 요구사항으로 준비하고 검증한다. 로컬 확인이 곧 해당 출시 요구사항의 완료를 뜻하지 않는다.
