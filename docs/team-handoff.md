## 함께 읽을 기준

1. [실행 체크리스트](onboarding.md)로 로컬 앱을 준비하고 현재 동작을 확인합니다. macOS 경로는 검증됐고 Windows 실제 실행은 **NOT RUN**입니다.
2. [서비스 범위](service-scope.md)에서 비회원·회원 경계와 첫 내부 목표를 확인합니다. [API 요청·응답](api.md), [DB 설계](database.md), [인증 구현 기준](authentication.md)은 향후 구현의 공통 기준입니다. 현재 라우트·테이블이 이미 있다는 뜻은 아닙니다.
3. 이슈에 적힌 범위대로 변경하고, [협업 흐름](workflow.md)에 따라 PR에 결과와 검사 기록을 남깁니다. PM `xifoxy-ru`가 공통 API·DB·보안 형식과 미정 결정을 정리하고 PR을 검토합니다. 각 담당자는 자기 구현과 검사를 맡습니다.

여기서 **테스트 예시(fixture)**는 실제 고객 정보 없이 만든 가짜 입력·예상 결과입니다. **확인된 사용자 정보(principal)**는 서버가 로그인 자격을 검사해 얻은 사용자 ID입니다. 화면에서 보낸 `user_id`만으로 소유권을 판단하지 않습니다.

## `yejoo0310`: S01 인증 예시

1. [#2](https://github.com/next-stop-siren/Next-Stop-Siren/issues/2)와 [API 인증 형식](api.md#인증-요청응답--후속-구현-기준)을 읽고, 가짜 사용자 ID·가입/로그인 입력·공개 응답 예시를 작성합니다.
2. 로그인하지 않은 요청의 `401`과 확인된 사용자 ID가 채팅 담당에게 전달되는 경우를 따로 보여 줍니다. 예시 토큰은 테스트 문자열만 사용합니다.
3. 채팅·화면 담당이 같은 형식을 읽을 수 있게 예시 위치와 요청·응답 검토 결과를 PR에 남깁니다. 실제 토큰 발급, 만료 처리, 새 인증 의존성 설치는 이 작업에 넣지 않습니다.

완료 확인 예: 가짜 사용자 `101`의 성공 응답과 인증 없는 요청의 `401`을 각각 재현할 수 있고, 실제 비밀값이 없습니다.

## `davekim-dev`: S07 내 대화 조회 예시

1. [#8](https://github.com/next-stop-siren/Next-Stop-Siren/issues/8)과 [DB 조회 예시](database.md#저장과-소유권)를 읽고, 사용자 `101`과 `202`의 가짜 대화·질문·완료 답변을 준비합니다.
2. 확인된 사용자 ID로 대화 소유자를 함께 제한하는 SQL과 예상 결과를 적습니다. 질문·답변 순서, 생성 시각, 실패·중단 답변이 다음 문맥에서 빠지는 경우를 보여 줍니다.
3. SQL·가짜 행·예상 결과를 PR에 남겨 인증·화면 담당이 확인할 수 있게 합니다. 실제 AI 호출이나 스키마 마이그레이션은 이 작업에 넣지 않습니다.

완료 확인 예: 사용자 `202`로 사용자 `101`의 대화를 조회하면 행이 나오지 않고, 완료된 답변만 다음 문맥에 포함됩니다.

## `gittul-123`: S15 비회원 화면

1. [#16](https://github.com/next-stop-siren/Next-Stop-Siren/issues/16), [서비스 범위](service-scope.md), [화면 지침](frontend.md)을 읽고 소개와 사람이 작성한 고정 예시를 구현합니다.

3. 화면 상태, 키보드 접근과 좁은 화면 확인, 비회원 접근 검사 결과를 PR에 남깁니다.

완료 확인 예: 로그인하지 않은 화면에서 예시는 볼 수 있지만 실제 전송·기록으로 들어갈 수 없고, 예시를 표시해도 AI·DB 호출이 없습니다.
