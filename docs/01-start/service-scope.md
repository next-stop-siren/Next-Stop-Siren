# 서비스 범위와 첫 작업

대기열·예약 한도·실행 전 취소·정지·복구는 PR #62까지 백엔드에 연결됐다. 인증 화면과 기본 HTTP 채팅도 있지만 실제 MemberChat의 작업·SSE 연동은 남았다. PR #58·#60·#61은 목업 범위다. 일반 제공자는 무료 mock이며 실제 AI·배포 완료를 뜻하지 않는다. [API](../04-reference/api.md)가 현재 계약의 단일 기준이다.

## 확정된 범위

- 이메일·비밀번호 가입과 Google 로그인을 제공한다.
- 이메일 인증과 비밀번호 찾기는 후속 범위로 둔다.
- 같은 이메일의 Google 계정과 로컬 계정은 별도 계정으로 유지한다.
- 이메일을 기준으로 계정을 자동 연결하지 않는다.
- 비회원에게는 소개와 사람이 작성한 고정 예시만 보여 준다.
- 로그인한 사용자에게만 실제 채팅과 대화 기록을 제공한다.
- 화면은 React `useState`, 서버는 FastAPI, 저장소는 PostgreSQL과 SQLAlchemy 2.x ORM을 사용한다. 선택한 구성과 현재 구현의 차이는 [기술 구성](stack.md)에 있다.
- 첫 내부 목표는 모의 제공자의 완성 답변을 저장하고 다시 조회하는 것이다.

## 데이터와 결정 경계

데이터의 논리 구조는 `users`, `auth_identities`, `refresh_sessions`, `conversations`, `messages` 다섯 기반 테이블과 한도 2개·대기열 3개를 합친 10개 ORM 모델이다. 사용자 소유권은 서버에서 확인한 사용자 정보(서버가 로그인 자격을 확인해 얻은 사용자 ID)를 기준으로 검사한다.

컬럼·관계·담당 순서와 구현 전 결정 경계는 [데이터베이스 설계](../04-reference/database.md)에 있다. 초기 범위에는 계정·대화 삭제 기능이 없고, FK `ON DELETE RESTRICT`는 참조되는 행의 삭제를 막는다.

가짜 테스트 데이터는 가짜 사용자와 응답만 사용한다.

다음 결정과 구현 검증이 남아 있다.

- 기존 스키마 변경·복구 절차와 데이터 보존 기간·일괄 삭제·백업 처리; 등록 모델 10개와 누락 테이블 초기화 명령은 구현됨
- 구현된 [인증](../04-reference/authentication.md)의 실제 화면 통합 검증과 Google 실패 복귀, 배포 Origin·키·Google client 및 공유 로그인 제한 방식
- [S11 GPT 어댑터](../04-reference/ai.md)의 격리 시험 증거와 공개 연결 경계 유지와 실제 스트리밍 어댑터
- PR #62 서버 대기열에 실제 MemberChat을 연결하는 구현과 #19·#54 검증

이 문서 정리는 실제 로컬 DB 초기화나 가입 실행 증거가 아니다. health/ready 성공도 인증 설정·제품 스키마 완성을 증명하지 않는다. 운영 입력과 전체 화면 통합 검증은 남아 있다.

## 담당과 작업 의존 관계

담당자별 실제 이슈 번호와 시작 순서는 [팀 작업 인계](../02-team/team-handoff.md)에 있다.

인증 `yejoo0310`은 #2 fixture와 #3 이후 인증·세션 흐름, 채팅·데이터 `davekim-dev`는 #3 → #9 → #8 → #10 → #11, 프런트엔드 `gittul-123`는 #16 → #17·#18 → #19 연결을 담당한다. 이 번호는 고정 작업 ID와 의존 관계이며 미구현 목록이 아니다. 이미 있는 구현·테스트를 먼저 읽고 실제 남은 범위와 검토 상태는 이슈·PR로 확인한다.

담당 역할은 [역할과 인계](../02-team/roles.md)를, 구현과 검증 흐름은 [협업 안내](../03-development/workflow.md)를 확인한다.
