## 현재 구현과 목표의 경계

PR #55에서 정책을 정하고 PR #56에서 API를 제안했다. PR #57·#59의 한도·영속 기반을 PR #62가 접수·실행·조회·취소·재시도·건너뛰기·회원 구독에 연결했다. 메시지 네 상태와 작업 여덟 상태는 별개다. 이전 동기 생성·연결 종료 시 생성 중단·60초 pending 회복·D4는 현재 계약이 아니다.

서버 대기열은 구현됐지만 실제 MemberChat의 `202`·작업·SSE·재시도·건너뛰기·취소·서버 시각 연결은 남았다. #18·#20·#21은 목업 범위로 종료됐다. 실제 연결 후속 이슈는 등록 필요하며 #19·#54 통합 검증이 열려 있다. 공개 AI는 무료 mock을 유지하고 실제 제공자 스트리밍과 운영 배포는 별도 작업이다.

정책이 요구하는 문맥 쌍 순서와 현재 ID 정렬 사이에는 차이가 있다. [API의 알려진 차이](api.md#알려진-구현-차이와-인수-확인)를 확인하며, 필터링의 존재를 순서 보장 완료로 표시하지 않는다.

## 회원 한도와 정산

| 항목 | 승인 값 |
| --- | --- |
| 일일 한도 | 회원당 400회, KST 00:00 초기화 |
| 6시간 한도 | 회원당 100회, KST 00:00·06:00·12:00·18:00 초기화 |
| 이월 | 없음 |
| 차감 단위 | DB에 완성 답변 저장이 확정된 생성 1회 |

새 질문과 수동 재시도의 **접수 때 일일·6시간 잔량을 함께 원자적으로 예약**한다. 대기열 입장과 예약이 일부만 성공하지 않아야 한다. 완료 답변 저장이 확정되면 예약을 1회 차감으로 정산한다. 실패·중단·실행 전 취소·대기 만료가 종결되면 예약을 한 번만 해제해 사용 가능 횟수로 되돌린다. 결과가 불명인 동안 예약을 유지하고 결과를 조정한 뒤 정산하거나 예약을 해제한다.

정산·예약 해제는 접수 당시의 일일·6시간 기간에 귀속한다. 초기화를 넘긴 옛 예약 해제는 새 기간의 잔량을 늘리지 않는다. 같은 키의 동일 요청을 재전송·재조회하면 새 예약·호출·차감 없이 기존 작업과 결과를 돌려주며, 남은 한도가 0이어도 가능하다. 사용자 한도 정산과 제공자 토큰·비용은 별개다. 제공자 호출이나 비용의 exactly-once를 보장하지 않는다.

## 입장과 실행 순서

- 회원 전체의 모든 탭·기기·대화에 걸쳐 실행 중 작업은 최대 1개다.
- 새 질문 대기는 최대 3개이며 실행 중 작업은 제외한다. 수동 재시도 대기는 회원당 별도 1개다.
- 실행 가능한 작업은 FIFO로 실행한다. 같은 대화의 실패 질문 재시도는 그 대화의 후속 질문보다 먼저 실행하지만 다른 실행 중 작업을 선점하지 않는다.
- 새 생성 시도 사이에는 최소 10초를 둔다. 자동 재시도는 없다. 같은 키의 결과 재조회는 새 생성 시도가 아니므로 이 간격으로 막지 않는다.
- AI 문맥은 접수 때 고정하지 않고 **실행할 때** 이전의 완료 질문+답변 쌍을 순서대로 읽고 현재 질문을 한 번 추가한다. 실패·중단·진행·부분 출력은 이력에 남기되 문맥에서 제외한다.

## 대기 취소와 만료

실행 전 작업만 취소할 수 있다. 실행 중 취소 API 동작이나 취소 버튼을 제공하지 않는다. 접수부터 5분이 지나면 아직 실행되지 않은 작업은 만료한다. 일시정지 중인 새 질문과 별도 재시도 대기도 포함하며, 정지·새로고침·재접속으로 기한을 연장하지 않는다. 실제 생성의 30초 기한은 대기 5분과 별도다. 실행 시작·취소·만료의 경합에서 하나의 결과만 반영하고 예약 해제를 중복하지 않는다.

## 실패, 재시도와 건너뛰기

실패·중단은 같은 대화의 후속 질문을 일시정지한다. 정지 중 새로 접수된 후속 질문도 정지하며 다른 대화는 실행할 수 있다. 실패 질문의 재시도가 성공하거나 사용자가 명시적으로 건너뛰면 후속을 재개한다. 재시도 실패·취소·만료는 정지를 해제하지 않는다.

재시도 대상은 **가장 최근 실행된 질문**이고 그 질문의 최신 답변이 `failed` 또는 `interrupted`여야 한다. 아직 실행되지 않은 뒤 질문의 접수만으로 재시도를 막지 않는다. 후속 질문이 실행을 시작한 뒤에는 앞 질문을 재시도할 수 없다. 수동 재시도 횟수는 제한하지 않는다. 각 새 시도는 새 키, 같은 시도 재전송은 같은 키를 유지한다. 새 시도는 한도·대기 자리·10초 간격을 검사한다. 화면은 서버가 허용한 동작만 표시한다.

## 연결, 로그아웃과 복구

연결 끊김·탭 닫기·새로고침·로그아웃은 서버 작업을 취소하지 않는다. 구독은 생성의 소유권이 아니다. 재접속하면 저장된 최종 결과를 조회한다. 놓친 delta 전체 재생은 이번 범위에 없다. 임시 delta는 저장 완료 답변과 구분하고 완료 저장 뒤에만 확정 결과를 보인다.

로그아웃은 해당 화면의 비공개 대화·임시 출력·구독을 지운다. 다른 회원에게 이 상태를 보여주지 않는다. 기존 access·refresh·logout 유효성 규칙을 바꾸거나 서버 작업을 취소하지 않는다. API는 접수·조회·구독·취소·재시도·건너뛰기 모두 검증된 회원과 소유권으로 제한한다.

서버 재시작 뒤 만료되지 않은 대기 작업은 복구한다. 실행 중이던 작업은 영속 완료 결과 또는 아직 유효한 실행과 조정한다. 해결되지 않는 실행은 중단으로 종결하며, 결과 불명 제공자 호출을 자동으로 다시 보내지 않는다. 늦은 이전 실행 결과가 종결 상태·새 시도·완료 답변을 덮어쓰지 못하게 한다. 제공자 쪽 생성·차감 중단은 보장하지 않는다.
