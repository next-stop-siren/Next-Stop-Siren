[회원 채팅 정책](chat-policy.md)은 실행 시 문맥과 연결 상태에 의존하지 않는 작업의 의도를 설명한다. 현재 경로·상태 계약은 [API](api.md)로 통합한다. 완료 쌍 필터링, 고정 제공자·모델, 30초 기한과 자동 재시도 금지는 유지한다.

수동 재시도 횟수 무제한은 사용자 요청 권한이며 자동 재호출 허용이 아니다. 결과 불명은 조정 전 예약을 유지하고 제공자를 자동 반복하지 않는다. 회원의 일일 400회·6시간 100회와 Codyssey의 주간 토큰 할당·비용은 별개이며 제공자 차감의 exactly-once를 보장하지 않는다.

이 문서는 **S11 / 이슈 #12**의 구현 계약과 격리 검증 기준이다. 현재 `CodysseyGptProvider`, 설정 파서, 대체 서버 검사와 명시적 live 스모크 경로가 있다. 공개 앱의 `get_provider()`는 계속 무료 mock이며 일반 가입·채팅에 실제 AI 키가 필요 없다. 이번 문서 검토는 실제 제공자 호출·검증을 새로 실행하지 않았다. **S10은 #11의 모의 답변 저장·재조회**, **S12는 #13의 스트리밍**이다.

## 제공자와 모델

| 항목 | 승인 기준 |
| --- | --- |
| 제공자 | Codyssey의 GPT API만 사용 |
| 모델 | 팀이 선택한 정확한 식별자 `gpt-5.5`로 고정 |
| 기본 URL | `https://copa.codyssey.kr/v1` |
| 요청 | `POST /chat/completions`; 전체 URL은 `https://copa.codyssey.kr/v1/chat/completions` |

모델을 사용할 수 없거나 요청이 실패하면 실패를 처리하고 자동으로 다른 모델·제공자로 대체하지 않는다. 현재 어댑터는 표준 라이브러리 `http.client`를 사용한다. 새 런타임 의존성을 추가하려면 별도 승인이 필요하다.

## 개인 키와 주간 할당

팀 배정은 **개발자마다 주간 500만 토큰**이다. 각 개발자는 자기 키를 자신의 백엔드/서버 `.env`에서만 사용한다. 프런트엔드 환경 변수·번들·브라우저·저장소·PR·로그·공유 화면에 키를 넣지 않는다. 키 공유나 한도 회피를 위한 키 교체·순환을 금지한다.

현재 파서는 서버 `.env`의 `CODYSSEY_API_KEY`, `CODYSSEY_BASE_URL`, `CODYSSEY_MODEL`을 읽고 고정 URL·모델이 아니면 거부한다. 이 설정만 넣어도 일반 앱 제공자가 실제 AI로 바뀌지는 않는다. 문서·검토에서 실제 키를 읽거나 출력하지 않는다.

남은 할당과 초기화 시각은 **Codyssey 대시보드**를 기준으로 확인한다. API 응답의 `usage` 토큰과 대시보드 할당 차감량이 같다고 가정하지 않는다. 확인하지 않은 배수·달러 비용을 계산하지 않는다. 별도 고정 시험 횟수·달러 상한은 두지 않는다. 실제 시험 전후 대시보드 상태를 확인하고 할당이 부족하면 중단한다.

## 호출과 대화 문맥

- 호출 시작부터 **30초 기한과 취소를 실제로 강제**한다. timeout 인자를 전달했다는 이유만으로 완료로 판단하지 않는다. 격리 어댑터의 요청 대기·취소와 timeout을 검증하고 늦은 결과가 종결된 답변을 덮어쓰지 못하게 한다. 제공자 쪽 생성이나 할당 차감까지 중단된다고 보장하지 않는다.
- HTTP 클라이언트·SDK·어댑터의 **자동 재시도는 끈다**. S10의 같은 키 재전송은 기존 결과 조회이며 새 제공자 호출이 아니다. 수동 재시도와 모의 스트리밍은 PR #62의 실행기에 연결됐다. 실제 Codyssey 어댑터에는 `complete`만 있고 `stream`이 없어 공개 연결은 별도 작업이다.
- 다음 GPT 입력은 **과거의 완성된 질문+답변 쌍을 순서대로 구성한 뒤 현재 질문을 한 번 추가**한다. `completed` 답변에 연결된 질문과 답변만 과거 쌍으로 포함한다.
- 과거 답변이 `failed`, `interrupted`, `pending`이면 그 질문과 답변을 **쌍 전체로 AI 문맥에서 제외**한다. 해당 기록은 DB와 UI 이력에 그대로 남긴다. 문맥에서 제외하려고 행을 삭제하거나 이력 조회를 필터링하지 않는다.

실행 경로 `chat_jobs.context_before()`는 완료 쌍을 질문 기준 쌍 순서(Q1·A1·Q2·A2)로 읽는다. 질문이 답변보다 먼저 여러 개 접수돼도 같다([#66](https://github.com/next-stop-siren/Next-Stop-Siren/issues/66), [API의 알려진 차이](api.md#알려진-구현-차이와-인수-확인)). 격리 어댑터·테스트 존재는 실제 AI 공개·브라우저 통합 완료 증거가 아니다. API 상태·저장 규칙은 [API 기준](api.md), 기록 구조는 [DB 설계](database.md)를 함께 따른다.

## 격리 시험과 인수 확인

실제 호출은 외부 공개 트래픽과 분리된 환경에서 가짜 사용자·합성 질문으로만 시험한다. 실제 사용자 대화·개인 데이터는 사용하지 않는다. 기본 CI와 자동 테스트에는 실제 호출을 넣지 않고 모의 제공자로 경계를 재현한다. 아래 인수 기준은 유지한다. 현재 코드·모의 테스트의 존재와 실제 실행 증거를 구분하며, 실제 스모크는 `--run-live`를 명시할 때만 동작한다. 명령·환경·DB 보호 조건은 [백엔드 안내](../03-development/backend.md#s11-gpt-어댑터와-격리-스모크-시험)에 있다.

- [ ] 격리 환경의 명시적 실제 스모크 시험에서 정확한 URL·`gpt-5.5`로 완성 답변을 받고 저장·재조회한다. 키나 질문·답변 원문을 증거에 넣지 않는다.
- [ ] 모의 실패·30초 시간 초과·취소·429/할당 부족을 재현하고 자동 재시도·모델 대체·추가 호출이 없음을 확인한다. 할당 소진을 만들려고 실제 토큰을 소비하지 않는다. 제공자 429 모의 실패는 기존 API 오류 계약에 따라 처리하며 새 HTTP 매핑을 정하는 항목이 아니다.
- [ ] 완성 쌍 여러 개 뒤 현재 질문이 한 번 들어가고, 실패·중단·진행 쌍은 양쪽 모두 문맥에서 제외되는지 확인한다. DB·UI 이력은 유지하고 사용자 소유권과 순서를 검사한다.
- [ ] 같은 키 재전송과 늦은 결과 처리 등 기존 저장·회복 계약을 유지한다.
- [ ] `trace_id`로 연결된 안전한 성공·실패 이벤트와 상태·소요 시간 등 메타데이터만 남긴다. 키·토큰·개인정보·질문·답변 원문을 로그나 API 오류에 넣지 않는다.

회원 한도는 PR #57·#62에서 연결됐다. 공개 서비스 개방에는 실제 AI `stream`, 문맥 순서 수정, 실제 화면 연결과 #19·#54·배포 검증이 필요하다. S11 격리 시험만으로 운영 준비가 끝났다고 표시하지 않는다.
