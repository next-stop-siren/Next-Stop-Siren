# 품질·테스트·비밀값

현재 로컬 테스트 명령은 저장소 루트의 `./local.sh test-unit|test-db|test-e2e|test`이며 Windows PowerShell에서는 `.\local.ps1`을 사용한다. `test-unit`은 DB 없이 API의 HTTP 응답·오류 경계, 테스트 DB 주소 보호, 화면 로딩·오류·재시도를 검사한다. 나머지 DB 명령은 README의 `TEST_DATABASE_URL` 명시 설정이 필요하다. `test-db`는 전용 테스트 DB에 읽기 전용 `SELECT 1`을 실행하고, `test-e2e`는 Chromium에서 실제 화면→API→테스트 DB 성공과 재현 가능한 오류 화면을 확인한다. `setup`은 잠금된 테스트 의존성과 프로젝트 Playwright 브라우저 캐시를 설치한다. 현재 인증·채팅·AI 기능과 해당 테스트는 아직 없다.

백엔드는 pytest와 HTTPX로 API의 정상 응답·입력 거부·오류 경계를 확인한다. 인증에서는 신규·기존 로그인, 만료·위조된 자격 증명, 갱신 토큰 폐기, 비인증 요청과 타인 기록 접근을 확인한다. 프론트엔드는 Vitest와 React Testing Library로 사용자에게 보이는 상태와 상호작용을 확인한다. Playwright는 먼저 실행 가능한 최소 화면→API 연동 스모크 테스트를 만들고, 기능이 정해지면 핵심 흐름의 E2E로 확장한다. 외부 AI 호출은 자동 테스트에서 모의 응답으로 대체해 성공·실패·시간 초과를 재현한다.

테스트 PostgreSQL은 개발 DB와 분리한다. 테스트 실행 전 접속 대상이 전용 테스트 DB인지 검사하고, 개발·공유 DB 주소면 중단한다. 픽스처는 최소 데이터만 만들고 테스트가 끝나면 정리한다. 실제 사용자 대화, 개인 정보, 토큰, 비밀값을 픽스처나 스냅샷에 넣지 않는다. 테스트가 실패하면 원인과 재현 방법을 남기며 통과한 척하지 않는다.

`.env`, 토큰, 키, 개인 데이터, 로그, 생성 캐시와 빌드 산출물은 Git에 넣지 않는다. 예시 설정에는 변수 이름·용도와 안전한 자리표시자만 둔다. 로그와 API 오류 응답에도 토큰, 키, 개인 대화 원문, 내부 연결 문자열을 남기지 않는다.

서버 기록에는 요청 수신, AI 호출 성공·실패, DB 저장 성공·실패를 같은 요청 단위로 연결해 확인할 수 있는 이벤트를 남긴다. 비밀번호나 개인 식별 정보도 기록하지 않는다.

PR에는 변경 범위에 맞춰 실행한 검사 명령과 결과를 적고, 실행하지 못한 검사는 이유를 적는다. 향후 CI는 포맷·린트·타입 검사, 서버·화면 테스트, 빌드, 분리된 테스트 DB를 이용한 통합 검사와 Playwright 스모크를 병합 기준으로 삼는다. 실제 환경에서 재현 가능한 명령과 결과가 마련되면 CI에 연결한다.

최종 공유 전에는 외부에서 접속 가능한 서비스 주소와 GitHub 저장소 링크를 실제로 확인한다. README와 기술 안내에 목적·대상 사용자·핵심 흐름, 구조와 구성요소, API 요청·응답 예시, DB 구조, 실행·배포 방법과 환경 변수, 팀 역할과 실제 작업을 담는다. 저장 결과를 확인할 수 있는 DB 확인 방법도 안내한다. 공개 예시에는 실제 사용자 데이터나 비밀값을 넣지 않고 확인한 결과만 기록한다.
