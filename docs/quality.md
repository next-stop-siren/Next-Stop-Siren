# 품질·테스트·비밀값

## 로컬 검사

현재 로컬 테스트 명령은 저장소 루트의 `./local.sh test-unit|test-db|test-e2e|test`이며 Windows PowerShell에서는 `.\local.ps1`을 사용한다. `test-unit`은 DB 없이 API의 HTTP 응답·오류 경계, 테스트 DB 주소 보호, 화면 로딩·오류·재시도를 검사한다. 나머지 DB 명령은 README의 `TEST_DATABASE_URL` 명시 설정이 필요하다.

`test-db`는 전용 테스트 DB에 읽기 전용 `SELECT 1`을 실행하고, `test-e2e`는 Chromium에서 실제 화면→API→테스트 DB 성공과 재현 가능한 오류 화면을 확인한다. `setup`은 잠금된 테스트 의존성과 프로젝트 Playwright 브라우저 캐시를 설치한다. 현재 인증·채팅·AI 기능과 해당 테스트는 아직 없다.

백엔드는 pytest와 HTTPX로 API의 정상 응답·입력 거부·오류 경계를 확인한다. 인증에서는 신규·기존 로그인, 만료·위조된 자격 증명, 갱신 토큰 폐기, 비인증 요청과 타인 기록 접근을 확인한다. 프론트엔드는 Vitest와 React Testing Library로 사용자에게 보이는 상태와 상호작용을 확인한다.

Playwright는 먼저 실행 가능한 최소 화면→API 연동 스모크 테스트를 만들고, 기능이 정해지면 핵심 흐름의 E2E로 확장한다. 외부 AI 호출은 자동 테스트에서 모의 응답으로 대체해 성공·실패·시간 초과를 재현한다.

테스트 PostgreSQL은 개발 DB와 분리한다. 테스트 실행 전 접속 대상이 전용 테스트 DB인지 검사하고, 개발·공유 DB 주소면 중단한다. 가짜 테스트 데이터(fixture)는 최소한만 만들고 테스트가 끝나면 정리한다.

실제 사용자 대화, 개인 정보, 토큰, 비밀값을 픽스처나 스냅샷에 넣지 않는다. 테스트가 실패하면 원인과 재현 방법을 남기며 통과한 척하지 않는다.

## 비밀값과 기록

`.env`, 토큰, 키, 개인 데이터, 로그, 생성 캐시와 빌드 산출물은 Git에 넣지 않는다. 예시 설정에는 변수 이름·용도와 안전한 자리표시자만 둔다. 로그와 API 오류 응답에도 토큰, 키, 개인 대화 원문, 내부 연결 문자열을 남기지 않는다.

서버 기록에는 요청 수신, AI 호출 성공·실패, DB 저장 성공·실패를 같은 요청 단위로 연결해 확인할 수 있는 이벤트를 남긴다. 비밀번호나 개인 식별 정보도 기록하지 않는다.

## PR과 CI 확인

PR에는 변경 범위에 맞춰 실행한 검사 명령과 결과를 적고, 실행하지 못한 검사는 이유를 적는다.

`.github/workflows/ci.yml`은 PR과 `main` push에서 단일 작업 **`B7-1 required checks`**를 정의한다. 프런트엔드 Biome 포맷·린트와 TypeScript 타입 검사, 백엔드 Ruff 포맷·린트와 mypy 타입 검사, 단위·로컬 자동화 테스트, 전용 테스트 DB 통합 검사, Playwright E2E, 빌드를 순서대로 실행한다.

Node 24.21.0/npm 11.19.0, Python 3.13.15/uv 0.11.19, Compose PostgreSQL 17.11을 사용한다. CI의 새 체크아웃에서만 `.env.example`을 `.env`로 복사하고 예시 테스트 DB 주소를 명시한다. 개발 DB를 시작하는 `setup`·`dev` 명령은 호출하지 않는다.

테스트 보호 로직이 주소와 실제 로컬 테스트 컨테이너·포트·볼륨을 확인한다. GitHub 호스티드 실행의 통과 여부는 해당 Actions 결과에서 확인하며 로컬 검사 통과로 대신하지 않는다.

현재 팀의 private Free 저장소에서는 `main` 보호 규칙으로 PR 리뷰와 필수 검사를 자동 강제할 수 없다. 팀은 유료 전환 없이 수동으로 운영한다.

PM은 병합 전에 실제 변경 diff, 담당자의 자체 확인 결과, 관련 담당자의 리뷰, CI 상태를 확인한다. 실패·미실행 검사가 있으면 이유와 후속 조치를 기록한다.

새 커밋으로 변경된 부분은 다시 확인한다. 권한 있는 사람이 확인 후 병합 커밋 방식으로 병합한다. `.github/CODEOWNERS`와 CI 정의만으로 검토나 병합 차단이 강제되지는 않는다.

GitHub 호스티드 검사 실행 여부는 실제 결과에서 확인한다.

최종 공유 전에는 외부에서 접속 가능한 서비스 주소와 GitHub 저장소 링크를 실제로 확인한다. README와 기술 안내에 목적·대상 사용자·핵심 흐름, 구조와 구성요소, API 요청·응답 예시, DB 구조, 실행·배포 방법과 환경 변수, 팀 역할과 실제 작업을 담는다. 저장 결과를 확인할 수 있는 DB 확인 방법도 안내한다.

공개 예시에는 실제 사용자 데이터나 비밀값을 넣지 않고 확인한 결과만 기록한다.
