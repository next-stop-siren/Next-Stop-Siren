# 품질과 설정

변경한 범위에 맞게 단위 확인, 서버 요청 확인, 화면 상태 확인을 고른다. 로그인과 사용자별 데이터 격리, 대화 문맥, AI 실패·시간 초과, DB 실패, 주요 화면 흐름은 재현 가능한 방법으로 확인한다. PR에는 실행한 확인 방법과 결과를 적고, 실행하지 못한 항목은 이유를 적는다.

서버는 요청 수신, AI 호출의 성공·실패, DB 저장의 성공·실패를 연결해 볼 수 있는 이벤트 기록을 남긴다. 비밀번호, 토큰, API 키, 개인 대화 원문 등 민감한 내용은 기록하지 않는다. 사용자에게 보여 주는 오류에도 비밀값과 내부 연결 정보를 담지 않는다.

실제 비밀 설정은 코드나 문서에 넣지 않는다. `.env` 파일과 실행 중 생기는 캐시·생성 파일은 Git에서 제외하고, 예시 설정 파일에는 필요한 항목의 이름과 용도, 비밀값이 아닌 안전한 자리표시자만 둔다. 설정이 바뀌면 영향을 받는 실행 안내와 확인 방법도 함께 갱신한다.

최종 공유 전 외부에서 접속 가능한 서비스 주소와 GitHub 저장소 링크를 확인한다. README와 기술 안내에는 프로젝트 목적·대상 사용자·핵심 흐름, 구조와 구성요소, API 요청·응답 예시, DB 구조, 실행·배포 방법과 환경 변수, 팀 역할과 각자의 실제 작업을 담는다. 평가자가 저장 결과를 확인할 수 있는 DB 확인 안내도 준비한다. 주소, 예시와 실행 방법은 실제 확인한 내용으로 기록한다.
